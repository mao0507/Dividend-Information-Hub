## 1) 核心旅程與最小可用條件（MVP DoD）

### A. 登入 / 註冊
- 使用者可完成登入或註冊，並在重新整理後仍可維持登入狀態。
- 失敗時需顯示可理解錯誤訊息（例如帳密錯誤、網路錯誤）。

### B. 儀表板
- 儀表板可載入摘要、即將事件與 Hero 區塊，不可只依賴假資料。
- 任一區塊失敗時需顯示可見錯誤或空狀態，不可靜默吞錯。

### C. 自選股
- 可新增股票、刪除股票、拖曳排序，並在重整後保持結果。
- 搜尋加入流程需可實際串接後端資料。

### D. 提醒中心
- 通知可讀取、標記已讀、全部已讀。
- 規則可新增、開關、刪除，且通知管道狀態需與後端能力一致。

### E. 設定
- 外觀設定、券商連結、同步偏好需具持久化（非記憶體暫存）。
- 非 MVP 的區塊需明確標記為規劃中，並避免造成可用性誤解。

### F. 全域搜尋（Command Palette）
- 搜尋結果可導向個股頁。
- Palette 的快捷動作不得為空操作。

## 2) 缺口分類規則

- 功能缺失：使用者目標無法完成（按鈕無作用、流程中斷）。
- 串接缺失：UI 存在但未對應有效 API 或 API 回傳未被處理。
- 資料真實性缺失：主要數據仍為假資料、暫存資料或不具持久化。
- 驗收缺失：缺乏可驗證條件或測試保護，導致回歸風險高。

## 3) 優先級判定（P0/P1/P2）

- P0：阻斷核心旅程或造成資料一致性/可用性重大問題，必須優先修。
- P1：功能可用但不完整或品質不足，影響中等，需排近期修復。
- P2：不影響主流程的體驗/文件優化，可延後處理。

## 4) 盤點輸出格式

- Metadata
  - timestamp
  - branch / change
  - audited scope
- Journey Status
  - flowName
  - status（可用 / 部分可用 / 不可用）
  - evidence（檔案、行為）
- Gap Detail
  - gapId
  - category
  - severity
  - reproduceSteps
  - expected
  - actual
  - impact
- Summary
  - total gaps
  - P0/P1/P2 count
  - next actions
