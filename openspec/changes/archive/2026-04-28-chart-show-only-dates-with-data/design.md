## Context

目前圖表資料由前端資料轉換層組裝後提供給 `TvChart` 與頁面元件。現況會把無有效價格的日期也帶入時間軸，導致折線中斷、視覺噪音與錯誤判讀。

此變更聚焦在前端資料契約：圖表只應渲染「有有效價格資料」的日期點，避免資料與時間軸不對齊。

## Goals / Non-Goals

**Goals:**
- 定義「有效資料日期」的判定規則，並在轉換層集中實作。
- 輸出給圖表的 labels 與 series 點位一一對齊。
- 對缺資料、混合資料與全空資料提供可預期行為。
- 建立測試，防止後續回歸。

**Non-Goals:**
- 不改動後端 API 格式與回傳欄位。
- 不新增圖表型態或交易所休市日曆功能。
- 不處理即時串流資料，只處理既有歷史日線資料渲染。

## Decisions

1. **在 chartData 轉換層做資料過濾（而非元件層）**
   - 理由：單一資料出口可同時服務 `DashboardPage` 與 `StockDetailPage`，避免多處重複判斷。
   - 替代方案：在 `TvChart.vue` 內過濾。缺點是頁面仍可能拿到髒資料，且難以單元測試。

2. **有效資料規則採最小必要條件：date 有效 + close 可解析且 > 0**
   - 理由：與現有股價語意一致，可排除 `null`、`NaN`、`0` 或異常字串。
   - 替代方案：僅檢查 date 存在。缺點是會把無效收盤價點渲染到圖上。

3. **labels 與 series 由同一份過濾後陣列映射生成**
   - 理由：從資料來源上保證索引一致，不依賴後續對齊修補。
   - 替代方案：先各自 map 再對齊。缺點是容易出現 off-by-one 或空洞點。

4. **空資料輸出為空陣列，不填補預設日期**
   - 理由：符合「只顯示有資料日期」需求，視覺語意最直接。
   - 替代方案：補齊最近 N 天。缺點是再次引入無資料日期。

## Risks / Trade-offs

- **[Risk] 過濾後點數變少，使用者體感資料被刪減** → 透過需求說明與測試確認此為預期行為（僅移除無效點）。
- **[Risk] 既有測試依賴固定點數可能失敗** → 同步更新測試 fixture 與斷言為「僅有效點」。
- **[Trade-off] 不補齊休市日，時間軸不再連續日曆日** → 換取資料真實性與可讀性，避免誤導。
