## Context

儀表板 Hero 區塊使用 `GET /stocks/:code`（與個股詳情同源）取得 `StockDetail`，其中 `price` 來自最新一筆 `StockPrice`，而 `change`／`changePct` 目前以「前一筆不同日期的收盤」推算。若種子價格序列與最新價差距過大、或僅有一筆價格卻沿用錯誤基準，會出現數千百分比等不可信數值。Hero 僅為摘要列，但仍必須符合使用者對「漲跌幅」的直覺。

## Goals / Non-Goals

**Goals:**

- 以清楚定義的「昨收／前一交易日收盤」計算漲跌額與漲跌幅，並在資料不足以計算時給出中性結果（例如 `changePct = 0` 或一致約定）。
- 儀表板 Hero 與個股詳情對同一檔股票在同一時間範疇內，不因不同頁面而採用矛盾的計算方式（共用同一後端邏輯）。
- 以單元測試鎖定邊界情境（單筆價、兩筆價、缺少昨收）。

**Non-Goals:**

- 不重做即時報價／券商串接。
- 不修正 K 線與報價不同步之市場特性（僅處理後端計算與資料一致性）。

## Decisions

1. **昨收定義**：以同一檔股票 `StockPrice` 依 `date` 遞減排序之「第二筆」收盤價為基準價（前一交易日）；若僅有一筆或無法取得第二筆，則 `change = 0`、`changePct = 0`（或設計文件與程式註解一致之單一約定）。

   - *替代方案*：用 `latest.close` 與「前一日曆日」列比對—易與假日／休市錯位，故不採。

2. **異常防呆**：若 `prevClose > 0` 且 `|changePct|` 超過約定門檻（例如 50%），視為資料異常，將 `changePct` 壓為 0 並可於開發環境 log（避免誤導正式使用者）。

   - *替代方案*：僅前端隱藏—後端仍錯，故採後端為主、前端可選。

3. **種子資料**：確認種子腳本中各檔 `StockPrice` 連續日期之收盤價平滑，避免「最新價來自詳情 seed、歷史僅六個月且起點價差過大」造成人工異常（必要時調整 featured 檔 seed 或 featured 選股邏輯）。

## Risks / Trade-offs

- [門檻防呆可能掩蓋真實暴漲暴跌] → 門檻僅用在種子／測試環境識別之異常區間，或設極高（如 50%）並文件化。
- [與使用者認知之「昨日收盤」不完全一致] → API 文件註明計算方式為「資料庫中前一筆交易日收盤」。

## Migration Plan

- 部署後無 schema 遷移；若需重種僅開發環境執行 `prisma seed`。
- rollback：還原 `stock.service` 計算區塊之 git commit。
