## Context

目前 Dashboard 上方卡片已具備統一資料模型與降級顯示原則，但「累積股息收入」仍缺少明確的資料語意（是否含未入帳、是否允許以 0 代表缺值）與跨卡片時間一致性約束。此變更同時影響前端顯示契約、資料轉換邏輯與可能的後端欄位補齊，因此需要先固定技術決策，避免功能完成後仍出現數值解讀爭議。

## Goals / Non-Goals

**Goals:**
- 明確定義「累積股息收入」僅採計可確認入帳且屬於指定統計期間的股息金額。
- 讓該卡片遵循 Dashboard 一致的狀態機（`ready`、`empty`、`stale`、`error`）與中性值策略。
- 將該卡片與 Hero/其他卡片對齊到同一 `asOf` 基準，避免同頁資料時序不一致。
- 建立可測試的行為場景，支援前後端回歸測試。

**Non-Goals:**
- 不重做整體 Dashboard 版面或卡片視覺設計。
- 不新增新的投資績效指標（如 IRR、總報酬率）。
- 不在此變更中處理歷史股息資料清洗策略重構。

## Decisions

1. **以新 capability 獨立定義累積股息收入契約**
   - 決策：新增 `dashboard-cumulative-dividend-income` spec，集中定義資料來源、計算口徑與狀態降級。
   - 理由：此指標有獨立商業語意，若只塞進既有 summary cards spec，後續擴充與測試邊界會模糊。
   - 替代方案：僅修改 `dashboard-top-summary-cards`。未採用原因：會把特定領域規則混入共用規格，降低可維護性。

2. **維持既有四卡統一模型，擴充欄位語意而非新增平行模型**
   - 決策：沿用 `title`、`displayValue`、`state`、`asOf` 的卡片模型，對累積股息收入補上 MUST 級語意約束。
   - 理由：可最小化前端模板變更，避免新增分歧渲染邏輯。
   - 替代方案：為累積股息收入建立單獨元件/模型。未採用原因：會破壞四卡一致渲染策略。

3. **缺值與異常一律使用中性顯示，不以 `0` 取代**
   - 決策：資料缺漏、格式錯誤、來源過期時，統一顯示 `--` 並對應狀態文案。
   - 理由：`0` 是有效財務值，不能承擔「未知」語意。
   - 替代方案：缺值顯示 `0` 並附 tooltip。未採用原因：容易被誤讀，仍可能造成判斷錯誤。

4. **跨來源資料採單次快照 `asOf` 對齊**
   - 決策：Dashboard 單次載入時，所有卡片與 Hero 採同一 `asOf`；任一關鍵來源失效時一起降級。
   - 理由：避免使用者在同頁看到互相矛盾的時間切片資料。
   - 替代方案：各卡片各自顯示來源時間。未採用原因：會提高認知負擔，且不利摘要決策。

## Risks / Trade-offs

- **[風險] 後端短期無法提供完整 `asOf` 或狀態欄位** → **Mitigation**：前端先以保守規則判定 `empty/error`，同時在 API 契約補齊後收斂判斷來源。
- **[風險] 歷史資料缺漏導致累積值波動** → **Mitigation**：在規格明確標示「僅含已確認入帳資料」，避免使用者誤解為完整歷史收益。
- **[取捨] 一致降級可能讓可用資訊被隱藏** → **Mitigation**：保留狀態文案與時間戳，讓使用者知道是資料一致性保護而非資料消失。
