## ADDED Requirements

### Requirement: 儀表板行情查詢必須以資料庫為第一來源
系統 MUST 在儀表板請求個股歷史行情時，優先從資料庫讀取符合標的與期間的時間序列資料；當資料庫存在可用資料時，MUST 直接回傳，不得先請求外部來源。

#### Scenario: 資料庫命中時直接回傳
- **WHEN** 使用者查詢 `stockCode=2330` 且資料庫於請求區間內有完整或部分可用日線資料
- **THEN** 系統直接回傳資料庫序列資料
- **AND** 不觸發外部來源回補流程

### Requirement: 僅在受控條件下觸發回補
當資料庫查無資料或資料不足以覆蓋請求區間時，系統 MUST 僅於回補開關啟用且同步狀態允許時觸發回補流程；若不符合條件，MUST 回傳結構化缺漏狀態。

#### Scenario: DB 缺漏但允許回補
- **WHEN** 查詢區間在資料庫無可用資料，且回補策略啟用、同步狀態允許
- **THEN** 系統觸發一次受控回補
- **AND** 回補完成後回傳最新可用序列

#### Scenario: DB 缺漏且不允許回補
- **WHEN** 查詢區間在資料庫無可用資料，且回補策略停用或同步狀態不允許
- **THEN** 系統回傳 `MISSING_IN_DB` 或 `SYNC_NOT_READY` 等對應狀態
- **AND** 回應中包含可追蹤原因訊息

### Requirement: 圖表資料回應必須支援部分可用資料
系統 MUST 允許回應包含「部分有效點位」並提供資料品質資訊，不得因單筆缺欄資料使整段圖表資料為空。

#### Scenario: 單筆異常不影響整體渲染
- **WHEN** 回應序列中存在少量缺欄或格式異常的點位
- **THEN** 系統回傳其餘有效點位
- **AND** 回傳中提供異常點位數與摘要，供前端顯示提示
