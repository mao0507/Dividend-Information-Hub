## Context

目前 Dashboard 四個統計卡（今日除息、本週除息、待填息、下次入帳）在可讀性與一致性上仍有風險：值雖顯示，但缺值、過期與時間格式容易讓使用者誤判為「資料正確」。使用者明確要求檢查「是否正常且完善」，因此需要把檢查標準規格化，將人工觀察轉為可重複驗證的品質門檻。

## Goals / Non-Goals

**Goals:**
- 定義四卡在 `ready`、`empty`、`stale`、`error` 的輸出規範（值、文案、時間格式）。
- 定義四卡與 Hero 共用 `asOf/freshness` 時的一致降級規則。
- 建立可重複驗收流程（單元測試 + 頁面測試 + 手動核對清單），可用於每次回歸檢查。

**Non-Goals:**
- 不改動後端資料來源與同步架構。
- 不重做卡片視覺設計與版面結構。
- 不新增資料指標，只檢查並完善既有四卡行為。

## Decisions

1. **以「驗收規格 + 測試證據」雙軌判定完善度**
   - 決策：品質檢查不是一次性肉眼確認，必須由規格條款（spec）定義，並綁定測試證據。
   - 原因：避免未來改動再次退化為「看起來正常但其實誤導」。
   - 替代方案：只做一次手動檢查；未採用，因為無法持續回歸。

2. **卡片值與文案分離判定**
   - 決策：值與文案分開驗證；例如 `empty/stale/error` 值一律 `--`，文案依狀態區分。
   - 原因：值正確不代表文案清楚，兩者都必須可測。
   - 替代方案：僅驗證值；未採用，因為會漏掉你這次截圖暴露的可讀性問題。

3. **時間格式可讀化列為必要條件**
   - 決策：禁止卡片直接顯示 ISO 原始時間字串，必須轉為使用者可讀格式。
   - 原因：ISO 直出雖 technically 正確，但對產品可用性不合格。
   - 替代方案：維持原始字串；未採用，因為不符合「完善」目標。

## Risks / Trade-offs

- **[Risk] 測試與人工驗證結果不一致** → 以 spec 中狀態定義為唯一判準，手動結果需對齊 spec。
- **[Risk] 過度嚴格造成頻繁 fail** → 先鎖定四卡核心條件（值/文案/時間格式），不擴張到視覺細節。
- **[Risk] 舊資料樣本不足觸發全部狀態** → 允許以 mock 測試補齊不可自然觸發情境。
