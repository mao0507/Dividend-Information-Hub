## Context

現有股息站以市場資料與股息資料為主，缺少使用者層級的持股成本與買入時間資訊，因此無法精準呈現個人化投資配置與報酬指標。本次變更需要跨前後端與資料庫，新增使用者持股紀錄資料流，並在儀表板提供兩個核心輸出：持股成本占比圓餅圖、以及自買入日起的累積除息收入。

## Goals / Non-Goals

**Goals:**
- 提供可持久化的使用者持股紀錄（股票代號、買入時間、買入價格、買入數量）。
- 提供可直接渲染圓餅圖的持股成本占比聚合資料。
- 提供以買入時間為下限的累積除息收入計算結果，作為使用者收益追蹤指標。
- 維持與既有股價/股息同步資料結構相容，避免重複維護市場主資料。

**Non-Goals:**
- 不處理賣出交易、庫存沖銷（如 FIFO/LIFO）與已實現損益。
- 不提供跨幣別換匯與手續費、稅務細項模型。
- 不在本次加入進階績效指標（IRR、XIRR、最大回撤）。

## Decisions

1. 使用「持股買入紀錄」作為最小資料單位，而非直接只存聚合庫存。  
   - 原因：買入時間會影響除息累積計算，必須保留批次買入明細才能正確過濾除息事件。
   - 取捨：查詢時計算成本與收入，讀取成本較高，但資料語意正確且可擴展至未來賣出模型。

2. 圓餅圖占比以「投入成本（買入價格 * 買入數量）」計算，而非即時市值。  
   - 原因：需求明確為「總投資金額」與「股票持有比重」，成本基準更穩定且不依賴即時報價可用性。
   - 替代方案：用最新市價計算市值占比；此方案波動大且受行情資料延遲影響，暫不採用。

3. 累積除息收入以「買入日（含）之後且股票代號相同」的除息紀錄加總。  
   - 原因：符合需求「從買入時間開始算已獲得多少除息收入」。
   - 計算邏輯：每筆買入批次收入 = 該股票在買入日後各次現金股利 * 該批次買入數量；最後對使用者全部批次加總。

4. API 採用分離式回傳：  
   - 持股 CRUD/查詢 API：管理明細資料。  
   - 儀表板聚合 API：回傳總投資、圓餅圖切片、累積除息收入。  
   - 原因：避免前端自行拼裝複雜商業邏輯，降低重複計算與不一致風險。

## Risks / Trade-offs

- [除息資料缺漏或延遲] → 使用現有資料同步狀態做可用性標記，當資料不完整時回傳 `dataAsOf` 與警示欄位。
- [使用者重複輸入同日同價同量紀錄] → 允許重複（視為不同交易），以主鍵 ID 管理，不做去重推斷。
- [聚合查詢效能下降] → 對 `userId + stockCode + buyDate` 建索引，並在儀表板查詢使用預先過濾條件。
- [需求擴充至賣出交易時模型需調整] → 保留買入批次明細作為未來擴充基礎，避免一次性聚合模型造成重構成本。
